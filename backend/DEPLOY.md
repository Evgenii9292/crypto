# FXMR4 · постоянный доступ с VPS (v2)

## Быстрое обновление текущего VPS

На Ubuntu 24.04 VPS 144.31.38.125 уже работает FXMR4 как systemd-сервис. Обновить без изменения сервиса на порту 8080:

```bash
cd /opt/fxmr4 && git pull --ff-only && bash deploy/upgrade-v2.sh
```

Скрипт проверяет бесплатный DNS `fxmr4-144-31-38-125.sslip.io`, устанавливает python3-cryptography, создаёт `FXMR4_SEAL_KEY` внутри приватного `/etc/fxmr4/fxmr4.env`, настраивает systemd StateDirectory, сохраняет прежний пароль и меняет только Caddy/FXMR4. Конфигурация Caddy предварительно копируется в файл резервной копии. Если DNS не работает, скрипт не трогает текущую конфигурацию.

После успешного выпуска сертификата сайт открывается с телефона по адресу:

`https://fxmr4-144-31-38-125.sslip.io`

Логин `fxmr4`, пароль прежний `FXMR4_PASSWORD`. API-ключ вводится только там, в разделе «Настройки → Подключения».

На телефоне вход выполняется через HTML-форму, без системного окна Basic Auth.
Пароль отправляется только в теле HTTPS-запроса. После входа сервер выдаёт
подписанную cookie с HttpOnly, Secure и SameSite=Strict на семь дней;
перезапуск приложения её не сбрасывает. Пароль не сохраняется в localStorage
или cookie. Прежняя Basic Auth остаётся доступной для штатных проверок.

В разделе фьючерсов история закрытий читается через `/api/closed-trades` из
Bybit `/v5/position/closed-pnl` за последние 30 дней: окна до семи дней,
все страницы, проверка повторных cursor и дедупликация по символу/orderId.
Неполная загрузка показывает ошибку. Кэш на пять минут принадлежит конкретному
ключу и хранится только в памяти; после рестарта история снова читается с биржи.
PNL показывается как передан Bybit, без повторного вычитания комиссий.
Это история закрытий linear-контрактов, включая частичные выходы, а не журнал
завершённых стратегий. Процент плавающего PNL считается от текущей equity
соответствующего подключённого субаккаунта. Время позиции использует Bybit
createdTime; оно не доказывает начало отдельного цикла стратегии.

## Защита и сохранение данных

- Новые Bybit API Key и API Secret строго **Read-Only** и для **субаккаунта**. Ключ после проверки через `/v5/user/query-api` сохраняется в `/var/lib/fxmr4/bybit.cred` в зашифрованном виде **AES-256-GCM**. Секретный ключ шифрования хранится отдельно в `/etc/fxmr4/fxmr4.env` с правами root (0600), а не в GitHub или браузере.
- Перезапуск `systemctl restart fxmr4` не стирает зашифрованный ключ и пользовательские данные. Потеря `FXMR4_SEAL_KEY` приведёт к невозможности расшифровать уже сохранённые API-ключи.
- Ручные покупки, плановый капитал, названия субаккаунтов, уровни докупок хранятся на VPS в `/var/lib/fxmr4/user-data.json`. Данные синхронизируются с браузерами по защищённым и авторизованным API-маршрутам, сохраняются атомарно и используют версии для разрешения конфликтов.
- Не вставлять ключи в GitHub, сообщения, логи, консоль или публичные страницы. При первом подключении ключ вводится только в форму сайта с действующим HTTPS. Отключение API удаляет файл с зашифрованными ключами.
- Сервер слушает только `127.0.0.1:8768`. Публичный доступ обеспечен Caddy на порту 443 по HTTPS, защищён дополнительным HTTP Basic Auth. Сервис на порту 8080 не затрагивается.
- Данные сохраняются на одном VPS. Для защиты от отказа диска впоследствии понадобится резервная копия вне этого сервера; версия v2 её пока не настраивает.

## Самый первый перенос покупок из localhost

Из-за политики браузера `http://localhost:8768` и новый публичный HTTPS-адрес хранят разные `localStorage`. Чтобы не потерять имеющиеся записи:

1. Открой обновлённый FXMR4 через прежний SSH-туннель **в том же браузере Mac**, где уже записаны покупки BTC/ETH. Дождись отметки «Сохранено на VPS» в левой боковой панели.
2. После этого открой новый публичный HTTPS-адрес на Mac или телефоне. Он загрузит записи с VPS.
3. Только теперь создавай новый Read-Only API-ключ Bybit, если старый ключ был удалён с биржи, и вводи его на HTTPS-сайте.

Если VPS-данных ещё нет, новый браузер без сохранённых покупок **не должен** создавать пустое состояние на сервере автоматически. Первым источником данных будет браузер, где уже записан портфель.

## Текущий бесплатный адрес хостинга

`bybitapi.vps.oblako.sh` был назначен VPS, но Let's Encrypt сообщил `NXDOMAIN` во время публичной DNS-проверки. Пока провайдер не обеспечил публичную A-запись, сертификат для него не получить. `sslip.io` позволяет использовать IP в бесплатном DNS-имени без покупки домена. Этот домен управляется сторонним сервисом, поэтому для долгосрочного production-доступа собственный домен надёжнее.

## Диагностика

```bash
systemctl status fxmr4 --no-pager -l
journalctl -u fxmr4 -n 30 --no-pager
journalctl -u caddy -n 50 --no-pager
curl -I https://fxmr4-144-31-38-125.sslip.io
```

Ожидаемый ответ `HTTP 401` означает, что HTTPS работает, но требуется авторизация.

# FXMR4 · подключение одного Bybit-субаккаунта

**Статус:** код готов в GitHub, но **на VPS не развернут**. Пока открываешь ссылку raw.githack.com, API-ключи вводить нельзя, и форма подключения намеренно отключена.

## Что уже реализовано

- Приватный Python HTTP-сервис на 127.0.0.1:8768 (не открыт напрямую в интернет).
- Дополнительная авторизация в FXMR4 через HTTP Basic Auth с длинным паролем.
- HTTPS через внешний reverse proxy Caddy; обычный HTTP с передачей ключей из браузера запрещён.
- Один Bybit субаккаунт. Только HMAC API Key типа Read-Only; API с правом записи или мастер-ключ отвергается через `/v5/user/query-api`.
- Реальный баланс UTA по `/v5/account/wallet-balance?accountType=UNIFIED`, открытые linear-позиции через `/v5/position/list?category=linear&settleCoin=USDT/USDC`, с пагинацией.
- Суммарная UTA equity, доступный баланс, плавающий PNL и список позиций показываются во Futures и в раскрывающемся Bybit-аккаунте.
- Если key/secret вводятся через интерфейс, сервер **не записывает их на диск** и теряет после перезапуска. Локальные сделки BTC/ETH не зависят от API.
- Приложение не умеет выставлять ордера, изменять плечо, выводить деньги или делать переводы.

## Настройка на Linux VPS

Все команды ниже предназначены для администратора VPS. Рекомендуется отдельный домен (например `fxmr4.your-domain.com`) с DNS A-записью на свой VPS и отдельным сертификатом HTTPS. **Не занимайте существующий порт 8080** и не заменяйте конфигурацию текущего сайта.

1. Установить Python 3.10+, git и Caddy. Убедиться, что порты 80 и 443 доступны для Caddy и DNS уже указывает на VPS.
2. Клонировать репозиторий в `/opt/fxmr4`. Например:

   `sudo git clone https://github.com/Evgenii9292/crypto.git /opt/fxmr4`

3. Создать системного пользователя `fxmr4` без доступа к оболочке:

   `sudo useradd --system --home /nonexistent --shell /usr/sbin/nologin fxmr4`

4. Подготовить окружение:

   `sudo mkdir -p /etc/fxmr4`

   `sudo install -m 600 /opt/fxmr4/deploy/fxmr4.env.example /etc/fxmr4/fxmr4.env`

   В файле `/etc/fxmr4/fxmr4.env` заменить `FXMR4_PASSWORD` на **уникальный длинный пароль** (не публиковать). Выбрать официальный домен API соответствующего типа Bybit-аккаунта: `https://api.bybit.com` либо `https://api.bybit.id`.

5. Установить службу:

   `sudo cp /opt/fxmr4/deploy/fxmr4.service /etc/systemd/system/fxmr4.service`

   `sudo systemctl daemon-reload`

   `sudo systemctl enable --now fxmr4`

6. Скопировать содержимое `deploy/Caddyfile.example` в отдельный блок конфигурации Caddy, заменить `fxmr4.example.com` на собственное доменное имя, затем проверить и перезагрузить Caddy.
7. Открыть HTTPS-ссылку. Браузер попросит логин `fxmr4` и пароль `FXMR4_PASSWORD`. Затем открыть «Подключения → Подключить субаккаунт», **на этом HTTPS-сайте**, и ввести созданные в Bybit API Key и API Secret.

## Настройки безопасности

- В Bybit ключ должен быть **Read-Only**. Приложение отклоняет ключи с `readOnly=0`.
- Предпочтительно ограничить ключ исходящим **публичным IP самого VPS**, через который он обращается к Bybit. Это может отличаться от адреса сетевого интерфейса при NAT.
- **Не публикуйте** `FXMR4_PASSWORD`, API Key или API Secret в GitHub, чатах, логах или браузерной консоли. Никогда не сохраняйте их в `localStorage`.
- Не ставьте `FXMR4_HOST=0.0.0.0`, не открывайте порт 8768 наружу. При желании ограничьте доступ к домену дополнительными правилами сети.
- Если Bybit выдаёт ошибку подписи, проверьте корректность ключа и времени VPS (NTP). Если ошибка региона, проверьте `BYBIT_API_HOST`. VPN в браузере не решает сетевой маршрут серверных API-запросов.
- Если интерфейс показывает `—`, это означает отсутствие проверенных данных, не нулевую позицию.

## Важное отличие Equity

Bybit Unified Trading Account объединяет активы и позиции. **totalEquity не равна отдельному депозиту Futures и может включать Spot**. Нельзя складывать вручную учтённый Spot и UTA equity без устранения возможного двойного счёта. Отображаем их отдельно, пока нет сверки.

## Обновление

`cd /opt/fxmr4 && sudo git pull --ff-only && sudo systemctl restart fxmr4`

Ручные покупки Spot из публичного GitHub-сайта хранятся в `localStorage` **его origin** и автоматически на новый домен не переносятся. Для переноса нужна отдельная функция импорта.

## API

- `GET /api/status`: готовность и статус ключа, без секретов.
- `GET /api/snapshot`: балансы, позиции и отметка времени, только после авторизации.
- `POST /api/connect`: ключ только с того же origin, с заголовком `X-FXMR4-Action: 1` и через HTTPS; ключ в памяти процесса.

Для текущего развертывания нужен фактический SSH-доступ к VPS и настройка DNS/HTTPS. Публикация кода в GitHub **не означает**, что этот сервер уже запущен.
