# FXMR4 · подключение одного Bybit-субаккаунта

**Статус:** код готов в GitHub, но **на VPS не развернут**. Пока открываешь ссылку raw.githack.com, API-ключи вводить нельзя, и форма подключения намеренно отключена.

## Что уже реализовано

- Приватный Python HTTP-сервис на 127.0.0.1:8768 (не открыт напрямую в интернет).
- Дополнительная авторизация в FXMR4 через HTTP Basic Auth с длинным паролем.
- HTTPS через внешний reverse proxy Caddy; обычный HTTP с передачей ключей из браузера запрещён.
- Один Bybit субаккаунт. Только HMAC API Key типа Read-Only; API с правом записи или мастер-ключ отвергается через `/v5/user/query-api`.
- Реальный баланс UTA по `/v5/account/wallet-balance?accountType=UNIFIED`, открытые linear-позиции через `/v5/position/list?category=linear&settleCoin=USDT/USDC`, с пагинацией.
- Суммарная UTA equity, доступный баланс, плавающий PNL и список позиций показываются во Futures и в раскрывающемся Bybit-аккаунте.
- Если key/secret вводятся через интерфейс, сервер **не записывает их на диск** и теряет после перезапуска. Локальные сделки BTC/ETH не зависят от API.
- Приложение не умеет выставлять ордера, изменять плечо, выводить деньги или делать переводы.

## Настройка на Linux VPS

Все команды ниже предназначены для администратора VPS. Рекомендуется отдельный домен (например `fxmr4.your-domain.com`) с DNS A-записью на свой VPS и отдельным сертификатом HTTPS. **Не занимайте существующий порт 8080** и не заменяйте конфигурацию текущего сайта.

1. Установить Python 3.10+, git и Caddy. Убедиться, что порты 80 и 443 доступны для Caddy и DNS уже указывает на VPS.
2. Клонировать репозиторий в `/opt/fxmr4`. Например:

   `sudo git clone https://github.com/Evgenii9292/crypto.git /opt/fxmr4`

3. Создать системного пользователя `fxmr4` без доступа к оболочке:

   `sudo useradd --system --home /nonexistent --shell /usr/sbin/nologin fxmr4`

4. Подготовить окружение:

   `sudo mkdir -p /etc/fxmr4`

   `sudo install -m 600 /opt/fxmr4/deploy/fxmr4.env.example /etc/fxmr4/fxmr4.env`

   В файле `/etc/fxmr4/fxmr4.env` заменить `FXMR4_PASSWORD` на **уникальный длинный пароль** (не публиковать). Выбрать официальный домен API соответствующего типа Bybit-аккаунта: `https://api.bybit.com` либо `https://api.bybit.id`.

5. Установить службу:

   `sudo cp /opt/fxmr4/deploy/fxmr4.service /etc/systemd/system/fxmr4.service`

   `sudo systemctl daemon-reload`

   `sudo systemctl enable --now fxmr4`

6. Скопировать содержимое `deploy/Caddyfile.example` в отдельный блок конфигурации Caddy, заменить `fxmr4.example.com` на собственное доменное имя, затем проверить и перезагрузить Caddy.
7. Открыть HTTPS-ссылку. Браузер попросит логин `fxmr4` и пароль `FXMR4_PASSWORD`. Затем открыть «Подключения → Подключить субаккаунт», **на этом HTTPS-сайте**, и ввести созданные в Bybit API Key и API Secret.

## Настройки безопасности

- В Bybit ключ должен быть **Read-Only**. Приложение отклоняет ключи с `readOnly=0`.
- Предпочтительно ограничить ключ исходящим **публичным IP самого VPS**, через который он обращается к Bybit. Это может отличаться от адреса сетевого интерфейса при NAT.
- **Не публикуйте** `FXMR4_PASSWORD`, API Key или API Secret в GitHub, чатах, логах или браузерной консоли. Никогда не сохраняйте их в `localStorage`.
- Не ставьте `FXMR4_HOST=0.0.0.0`, не открывайте порт 8768 наружу. При желании ограничьте доступ к домену дополнительными правилами сети.
- Если Bybit выдаёт ошибку подписи, проверьте корректность ключа и времени VPS (NTP). Если ошибка региона, проверьте `BYBIT_API_HOST`. VPN в браузере не решает сетевой маршрут серверных API-запросов.
- Если интерфейс показывает `—`, это означает отсутствие проверенных данных, не нулевую позицию.

## Важное отличие Equity

Bybit Unified Trading Account объединяет активы и позиции. **totalEquity не равна отдельному депозиту Futures и может включать Spot**. Нельзя складывать вручную учтённый Spot и UTA equity без устранения возможного двойного счёта. Отображаем их отдельно, пока нет сверки.

## Обновление

`cd /opt/fxmr4 && sudo git pull --ff-only && sudo systemctl restart fxmr4`

Ручные покупки Spot из публичного GitHub-сайта хранятся в `localStorage` **его origin** и автоматически на новый домен не переносятся. Для переноса нужна отдельная функция импорта.

## API

- `GET /api/status`: готовность и статус ключа, без секретов.
- `GET /api/snapshot`: балансы, позиции и отметка времени, только после авторизации.
- `POST /api/connect`: ключ только с того же origin, с заголовком `X-FXMR4-Action: 1` и через HTTPS; ключ в памяти процесса.

Для текущего развертывания нужен фактический SSH-доступ к VPS и настройка DNS/HTTPS. Публикация кода в GitHub **не означает**, что этот сервер уже запущен.
